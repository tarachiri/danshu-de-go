## 背景・確定した根本原因

Googleサーチコンソールで `https://dansyu-go.nukadokonokai.com/` が
「クロール済み - インデックス未登録」のステータスになっている。

調査で判明した事実：

- noindexタグ：無し（robots.txt・HTML双方とも）
- meta description・OGP基本タグ・google-site-verification：実装済み
- `<body>`内の静的テキスト量：約246文字（UIラベルのみ、実質的な説明文なし）
- 例会・会場データ（会場名・住所・日程等）は生HTMLに一切含まれない
  → `#map` `#schedule` `#news` `#kamo` `#sheet-content` はすべて空の `<div>`
  → `app.js` が `venues.json` / `schedule.json` をfetchしてJSで描画する構造

結論：技術的なブロック要因は無い。Googlebotから見て「独自性・情報価値のある
ページ」と判定されるだけの静的コンテンツが存在しないことが根本原因（Thin Content）。

## 対策方針

JS描画のアーキテクチャ（Myカレンダー機能等の土台でもあるため）は変更しない。
その代わり、`venues.json` から都道府県別・例会別の静的HTMLサマリーを生成し、
`index.html` に常時可視のセクションとして埋め込む。

ユーザーにも完全に見える形とする（非表示・視覚的最小化は行わない。
Googleの隠しテキストとみなされるリスクがあるため明確に非推奨）。

venues/meetings責務分離の原則に従い、`meeting_name` が空のレコード（施設のみの
登録、例会情報が紐づいていないもの）はこのサマリーから除外すること。
施設が例会予定を代弁すべきでない、という既存の設計原則をここでも守る。

## 実装内容

### 1. 新規スクリプト：danshu-tools/generate_seo_summary.py

入力：tyo本番の `venues.json`（`generate_map_v6.py` の出力）

処理：

1. `venues.json` を読み込み
2. `meeting_name` が空文字でないレコードのみ抽出
3. `prefecture` ごとにグルーピング
4. 各都道府県内で会場名・例会名・住所・曜日/時間（分かる範囲）を整形
5. 以下の構造でHTML断片を生成し、ファイルに書き出す（出力先パスは既存の
   生成物と同様の場所を想定。ふーちゃん判断でOK）

```html
<section id="seo-summary">
  <h1>断酒でGO!! 断酒会 例会情報マップ</h1>
  <p>全日本断酒連盟に加盟する断酒会の例会情報を、地図とスケジュールで検索できます。
     アルコール依存症からの回復・断酒継続を目指す方への支援情報です。</p>

  <h2>東京都の断酒会 例会一覧</h2>
  <ul>
    <li><strong>◯◯例会</strong> - 住所（会場名）曜日 時間</li>
    ...
  </ul>

  <h2>神奈川県の断酒会 例会一覧</h2>
  ...
</section>
```

冪等性：venues.jsonが変わるたびに再生成される前提。既存の
`_flattenVenuesToSchedule()` 等と同様、実行のたびに全体を作り直す形でよい
（差分更新は不要）。

文言について：依存症・アルコール依存症・例会・回復・支援・断酒等の言葉が
自然に含まれる構成に既になっているので、無理に追加ワードを詰め込む必要はない。
不自然なキーワード羅列（キーワードスタッフィング）はGoogleのスパム判定対象に
なりうるため避けること。

### 2. index.html への組み込み

- `#map` セクションの後、ボトムナビ（`#bottom-nav`）の手前に `#seo-summary` を配置
- 生成されたHTML断片をそこに挿入する形で index.html をビルド/更新する
- 既存の地図・タブ切り替え・PWA機能のDOM構造・JS処理には一切影響を与えないこと

### 3. style.css への追記

- 新規クラスを追加し、既存のダークテーマ（背景 `#1a1a2e`、アクセント `#e94560`）に
  トーンを合わせる
- `display: none` 等の非表示指定は一切使用しないこと（重要）
- 折りたたみ（details/summary）も使わず、スクロールすれば読める通常のセクションとする
- 見出し（h1, h2）・リストが視覚的にも自然に読める最低限のスタイルでよい
  （凝ったデザインは不要、可読性優先）

### 4. cron登録

- tyo上で `generate_map_v6.py`（毎日5:00 AM）実行後の追加ステップとして
  `generate_seo_summary.py` を登録
- 実行順序：`generate_map_v6.py` → `generate_seo_summary.py` →
  （必要なら index.html への反映・git push まで自動化するか、生成のみ自動化して
  commit/pushは人間確認を挟むか、ふーちゃん判断でOK。ただし本番反映前の
  dry-run→まじまじさん確認→本番適用の原則は守ること）

## 動作確認

1. ローカルで生成後の index.html を開き、地図・フィルター・日程/お知らせタブが
   従来通り動作することを確認
2. ブラウザの「ページのソースを表示」で `#seo-summary` に実データが含まれている
   ことを確認（JS実行前の生HTMLとして存在することが必須）
3. スクロールして `#seo-summary` セクションが実際に見えることを確認
4. https://search.google.com/test/rich-results でHTML/URLを検証し、エラーが
   無いことを確認

## 完了条件

- `venues.json` 内の実例会データが、JS実行前の静的HTMLとして `index.html` に
  可視の形で含まれること
- 既存の地図・PWA・タブ機能に影響がないこと
- キーワードスタッフィングや隠しテキストに該当する実装になっていないこと

## 補足：このタスクの位置づけ

現行タスクリストの「①ハンバーガーメニュー復活（chiiki/導線・SEO内部リンク）」とも
関連が深い。将来的に都道府県別・断酒会別の個別ページ（内部リンク構造）ができれば、
このSEOサマリーはそれらへのリンク集としても機能拡張できる。今回はまず
「クロール済み-未登録」を解消する最小限のスコープに留める。
